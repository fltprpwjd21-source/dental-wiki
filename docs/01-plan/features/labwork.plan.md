## 1. Overview

### 1.1 Purpose

기공물 장부에서 **"오늘 와야 할 것이 왔는지"**를 진료 중에 폰으로 확인할 수 있게 한다.
장부 자체를 앱으로 옮기는 것이 아니다.

### 1.2 Background

지금 시스템은 구글 시트 + Apps Script 네 조각이다.

| 조각 | 하는 일 | 환자정보 |
|---|---|---|
| ① 기공물 목록 장부 | 기공소와 주고받는 기공물 테이블 | 이름·차트번호 있음 |
| ② 예약 명단 시트 | 구글 캘린더에서 환자 예약을 끌어옴 (Apps Script) | 예약 명단 |
| ③ 도착 확인 시트 | 도착 예정일 기준으로 오늘 와야 할 것을 추림 | ①을 참조 |
| ④ 월별 통계 메일 | 종류별 개수를 집계해 매월 1일 이메일 (Apps Script) | 없음 (집계 수치만) |

네 조각 중 **③만 앱으로 옮긴다.** 실제 쓰임이 있고, 폰에서 봐야 하는 것이 이것뿐이다.

## 2. Scope

### 2.1 In Scope

1. **오늘 화면** — 지남 → 오늘 → 예정 순으로 정렬. 읽어 보여주고 끝낸다(저장하지 않는다)
2. **「도착」 쓰기** — 앱에서 누르면 시트에 기록한다
3. **환자 이름 가리기** — 가운데 한 글자만 `○`로. 화면에 그릴 때만 적용
4. **홈 요약** — 「오늘 도착 예정 N건 · 지남 N건」
5. **월별 통계 화면** — 종류별 개수. 집계 수치만 우리 DB에 캐시
6. **원본 교체 가능한 구조** — 읽기 코드를 `lib/labwork/source.ts` 한 곳에 몰아넣는다

### 2.2 Out of Scope

- **장부 입력** — 기공사가 시트에서 계속 한다. 입력은 시트가 웹 표보다 빠르다
- **예약 명단(②)** — 앱에 가져오지 않는다. PRD ⑦에 "환자 예약 일정은 넣지 않는다"고 이미 정해 두었다
- **통계 이메일(④)** — Apps Script 유지. 보류 (7.2 참고)
- **환자 개인식별정보의 우리 DB 저장** — 현 단계에서는 하지 않는다 (7.2 참고)

### 3.3 환자 이름 가리기 규칙

가운데 한 글자만 `○`로 바꾼다. 저장하지 않고 화면에 그릴 때만 적용한다.

| 이름 | 표시 | 비고 |
|---|---|---|
| 김민수 | 김○수 | 가장 흔한 3글자 |
| 김수 | 김○ | 2글자는 뒤를 가린다 — 앞을 가리면 성이 사라진다 |
| 남궁민수 | 남궁○수 | 4글자는 가운데 한 글자 |
| 김 | 김 | 1글자는 가릴 것이 없다 |

순수 함수(`lib/labwork/mask.ts`)로 만들고 위 표를 그대로 테스트에 넣는다.

> **이 규칙은 임시일 수 있다 (2026-09-09 사용자 판단).**
> NAS 로 옮기면 가릴 필요가 없어진다고 보아 그때 지울 예정이다.
> 다만 가리는 이유가 둘이라는 점은 남겨 둔다 —
> **(가) 저장 위치**: 환자정보를 외부 클라우드에 두지 않기 위해. NAS 로 가면 해소된다.
> **(나) 화면 노출**: 진료실 화면은 환자·보호자가 지나가며 본다. 이건 어디서 돌리든 그대로다.
> (가)만 보고 지우면 (나)가 조용히 사라지므로, 지울 때 (나)를 받아들이는 판단인지 확인한다.
> 지우기는 쉽다: `lib/labwork/mask.ts` 와 그 테스트를 지우고 화면에서 이름·차트번호를
> 그대로 이어붙이면 된다. 다른 곳에서 부르지 않는다.

## 7. Architecture Considerations

### 7.1 Project Level Selection

Dynamic. 새 인프라를 들이지 않고 기존 Next.js + Postgres 위에 화면 하나와 외부 읽기 하나를 더한다.

### 7.2 Key Architectural Decisions

**결정 1 — 장부 원본은 구글 시트에 둔다 (지금 단계)**

- 기공사가 쓰는 도구를 바꾸지 않는다. 사내 시스템이 실패하는 첫째 이유가 "기존 방식보다 불편해서"다
- 환자 이름·차트번호가 Supabase(외부 클라우드)에 저장되지 않는다
- Apps Script 자동화를 지우지 않아도 된다
- 앱이 망가져도 장부는 멀쩡하다

**결정 2 — 나중에 NAS 로 가면 원본을 우리 DB로 옮기는 것을 검토한다**

지금 환자정보를 우리 DB에 못 넣는 이유는 **Supabase 가 외부 클라우드**라서다.
NAS 는 병원 안 우리 장비이므로 그 제약이 사라진다.

> 짚어둘 것: **지금도 환자 이름·차트번호가 구글 시트(= 외부 클라우드)에 있다.**
> "환자정보 외부 반출 금지" 원칙은 이미 지켜지지 않는 상태이고,
> NAS 이전은 그것을 고치는 방향이다. 미루는 이유가 아니라 옮길 명분이다.

그래서 **갈아끼울 자리를 지금 만든다.**

```
lib/labwork/types.ts     화면이 받는 타입 (원본이 무엇이든 이 모양)
lib/labwork/source.ts    원본에서 읽어오는 유일한 창구
   └─ 1단계: 구글 시트 구현
   └─ 2단계: 우리 DB 구현으로 교체 (화면·API·타입은 그대로)
```

읽기 코드가 흩어지면 이전할 때 전부 찾아 고쳐야 한다. 한 파일이면 그 파일만 바꾼다.

**NAS 이전 난이도 (2026-09-09 실측)**

| 항목 | 상태 | 이전 시 |
|---|---|---|
| 로그인·세션 | Supabase Auth 미사용 (자체 사원번호 세션) | 그대로 |
| DB 함수 18개 | 표준 `plpgsql`/`sql` | 그대로 |
| pgvector | 표준 확장 | 그대로 |
| RLS | 정책이 아니라 차단용으로만 사용 | 사실상 불필요 |
| 접속 계층 | `lib/supabase/server.ts`·`browser.ts` 2개 파일 | 이 2개만 교체 |
| 파일 저장 | `lib/file-storage.ts` 1개 파일 | 이 1개만 교체 |
| 임베딩 차원 | `vector(1536)` 이 마이그레이션 6곳에 박힘 | 차원 변경 + 전체 재색인 |
| Vercel Cron | 1개 (`purge-trash`) | OS cron 으로 대체 |

Supabase 는 오픈소스라 NAS 에 Docker 로 그대로 띄울 수 있다. 그 경우 Storage·DB함수·RLS 가
전부 동작하고 접속 URL·키만 바뀐다. **지금 구조는 이미 그 이전을 견딘다.**

임베딩 차원은 **지금 서두르지 않는다.** 조각이 78개뿐이라 나중에 전체 재색인해도 몇 분·몇 센트다.
로컬 모델을 실제로 골라본 뒤 정한다 (한국어는 `bge-m3` 1024차원이 후보).

**결정 3 — 상태색은 기공물 화면 안에서만 쓴다**

| 상태 | 색 |
|---|---|
| 예정일 지남 | 빨강 `--late` |
| 오늘 도착 예정 | 주황 `--soon` |
| 도착함 | 초록 `--done` |

> **홈 캘린더에 기공물 예정일을 점으로 찍을 때는 주황을 쓰지 않는다.**
> 주황은 「공지에서 지정한 날짜」 전용으로 예약돼 있다 (DESIGN.md, 2026-09-08 결정).
> 캘린더에 얹을 때는 파랑 계열을 쓴다. 기공물 화면 안의 배지는 캘린더가 아니므로 주황을 써도 된다.

**결정 4 — 통계 이메일(④)은 보류**

Apps Script 가 이미 무료로 잘 보낸다. Vercel 에서 보내려면 발송 서비스를 새로 붙여야 하고
(지금 없다) 발신 주소 인증·무료 한도를 따로 설정해야 한다. 앱에는 **통계 화면**을 두어
이메일을 기다리지 않고 아무 때나 볼 수 있게 하고, 이메일 이전 여부는 NAS 시점에 판단한다.

## 8. Convention Prerequisites

착수 전에 두 가지가 필요하다. **둘 다 사용자만 할 수 있다.**

### 8.1 구글 서비스 계정 (아직 없음)

2026-09-09 확인: `.env` 에 구글 관련 값이 하나도 없고 구글 패키지도 설치돼 있지 않다.
PRD ⑦ 캘린더 연동이 "구글 콘솔 세팅 직전"에 멈춘 그 지점이다.

1. 구글 클라우드 콘솔에서 서비스 계정 생성 → JSON 키 발급
2. Google Sheets API 활성화 (캘린더까지 하려면 Google Calendar API 도 함께)
3. 기공물 시트를 그 서비스 계정 이메일에 **편집자**로 공유
   — 「도착」을 앱에서 쓰기로 정했으므로 뷰어로는 부족하다
4. JSON 키를 `.env` 에 넣는다. 직원 개개인의 구글 로그인은 요구하지 않는다

**기공물과 근무 캘린더가 같은 서비스 계정을 쓴다.** 한 번 만들면 둘 다 열린다.

### 8.2 시트 첫 줄 (열 이름)

열 이름을 모르면 읽는 코드를 쓸 수 없다. 첫 줄만 그대로 붙여주면 된다.

필요한 것: 기공물 종류 / 기공소 / 의뢰일 / **도착 예정일** / **도착 여부** / 환자 이름 / 차트번호

### 8.3 Environment Variables Needed

| 변수 | 용도 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스 계정 키 (서버 전용) |
| `LABWORK_SHEET_ID` | 기공물 장부 스프레드시트 ID |
| `LABWORK_SHEET_NAME` | 장부가 있는 시트(탭) 이름 |
